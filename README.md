## About OpenToolbox

**OpenToolbox** is an open-source collection of **122 browser-based utilities** for writing, development, design, images, data conversion, accessibility, PDFs, dates, finance and everyday calculations.

The project is designed for people who need quick, dependable tools without installing software, creating an account or uploading private content to an application server. Most processing happens locally on the visitor's device using standard browser APIs.

### Project principles

- **Free** — every tool is available without a subscription.
- **Useful** — focused utilities for real tasks rather than demonstration-only features.
- **Privacy-focused** — most inputs and files stay inside the browser.
- **Browser-based** — no desktop application is required.
- **Accessible** — keyboard support, clear focus states and semantic page structure.
- **Mobile-friendly** — responsive interfaces for phones, tablets and desktop computers.
- **Easy to deploy** — static hosting with no production build step.
- **Open source** — inspect, adapt and improve the project under the MIT Licence.

## Key Features

### Fast browser utilities

Open a tool, add the required input and receive the result immediately. Each utility has its own indexable URL, clear instructions and a focused interface.

### Local file processing

Supported images and PDFs are inspected or transformed through browser APIs. The project does not operate an application server that receives those files.

### My Toolbox

Visitors can create a personalised workspace containing:

- Favourite tools
- User-defined favourite collections
- Recently opened and recently used tools
- Custom homepage category order
- Hidden or visible homepage categories
- Optional locally saved tool inputs
- Exportable and importable local settings
- A complete local-data deletion control

### Offline availability

OpenToolbox includes:

- A web app manifest
- Service-worker caching
- An offline fallback page
- Install controls where supported
- Runtime cache refreshes for updated assets

### Responsive design

The interface is designed for desktop browsers, laptops, tablets, mobile phones, touch input and keyboard-only navigation.

### Light and dark themes

Both themes use shared design tokens so cards, forms, buttons, dialogs, hints, result areas and dashboards remain readable and consistent.

## Privacy by Design

OpenToolbox is intentionally built without an application backend.

### What stays local

The following are normally processed or stored only on the visitor's device:

- Text entered into tools
- Selected image files
- Selected PDF files
- Favourites
- Collections
- Usage history
- Category preferences
- Theme and interface settings
- Optional saved form inputs

Local preferences use browser `localStorage`. Visitors can export, import or delete this data from **My Toolbox**.

### Limited external resources

| Tool | External resource | Purpose |
|---|---|---|
| Currency Converter | Frankfurter API | Retrieves reference exchange-rate data |
| QR Code Generator | jsDelivr-hosted QRCode.js | Loads the MIT-licensed QR rendering library when required |

GitHub Pages may process ordinary hosting logs according to GitHub's own policies.

Read the complete [Privacy Policy](privacy.html).

- Accessible labels for controls

Accessibility tools provide helpful checks, but they do not replace a complete professional audit with assistive technology and human testing.

## Run OpenToolbox Locally

Many tools work when `index.html` is opened directly, but service workers and some browser APIs work best through a local web server.

### Python

```bash
python -m http.server 8000
```

Then open:

```text
http://localhost:8000/
```

### Node.js

```bash
npx serve .
```

Then open the local address shown in the terminal.

## Deploy with GitHub Pages

### GitHub Desktop

1. Clone or open the `open-browser-toolbox` repository in GitHub Desktop.
2. Copy the updated project files into the local repository folder.
3. Review the changes.
4. Commit the update to the `main` branch.
5. Push the commit to GitHub.
6. Open the repository's **Settings**.
7. Open **Pages** under **Code and automation**.
8. Select **Deploy from a branch**.
9. Choose `main` and `/ (root)`.
10. Save the settings.
11. Wait for GitHub Pages and GitHub Actions to finish.

The project does not require a build command.
